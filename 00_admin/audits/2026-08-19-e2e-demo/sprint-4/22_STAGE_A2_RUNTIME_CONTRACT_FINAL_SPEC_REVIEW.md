## Verdict

The report 19 and report 20 adversarial cases are now rejected by the schema-first production validator, and the focused 16-test gate, six-schema meta-validation, and live prompt/output hash validation pass. However, A2.1 is not approvable because a next-step Context Package can bind `project_context` in `project_v2` mode to a `released_predecessor` descriptor while keeping an unrelated valid `project_v2` descriptor in `sources`. This is a locally representable record relationship and makes the required Project V2 binding ambiguous before deferred A2.2 repository resolution.

No provider, network, API, event, simulator, UI, routing, workflow-state, prompt, output-contract, or deployment behavior was exercised or changed by this review.

### P1: Context Package does not bind project_context to a matching project source kind

Files: `standards/runtime/context-package.schema.json`, `services/runtime_contracts/llm_records.py`, `tests/test_llm_runtime_invariants.py`

For `trigger: next_step`, the schema requires exactly one `project_v2` source and the package's `project_context.binding_mode` is `project_v2`. The production invariant validator then finds one source by `source_id` and compares revision, logical reference, and content hash. It does not require the matched source to have `source_kind: project_v2`. Therefore a caller can point `project_context` at a released predecessor while retaining an unrelated Project V2 source solely to meet schema cardinality.

This violates controller plan 17 requirements for an exact project context binding and the Step 0 versus Step 1+ authoritative input distinction. It also conflicts with DEC-0019, which requires exact immutable context sources for reproducible runs. A2.2 may verify the selected descriptor against stored bytes, but it cannot choose the intended authoritative project source from this ambiguous A2.1 package.

Required correction: require the source matched by `project_context` to have `source_kind` consistent with `binding_mode`, and add direct production-validator negative tests for the Step 0 intake and Step 1+ Project V2 kind-swap cases. Re-run this review's command set after correction.
